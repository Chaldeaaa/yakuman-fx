Yakuman FX 使用实际和牌手牌，恢复游戏内置的 Unity 役满特效。安装后在大厅启用一次，以后打开游戏就会自动启用。无需 Steam 客户端、桌面辅助程序或命令行窗口。扩展界面支持 English／简体中文，可通过右上角齿轮进入设置切换语言，并选择浅色／深色／跟随系统主题。

## 安全性与修改范围

Yakuman FX 专注于原生役满动画的本地呈现。与通过改写角色、背包或装扮信息来显示未拥有皮肤的工具相比，本项目的修改范围更窄，不涉及角色或装扮的拥有状态。

| 对比项 | Yakuman FX | 通过改写账号数据实现的皮肤解锁工具 |
| --- | --- | --- |
| 修改目标 | 役满动画开关、资源加载和音效逻辑 | 客户端收到的角色、皮肤或装扮数据 |
| 游戏通信 | 不拦截或改写游戏 WebSocket 消息 | 通常需要拦截或改写相关消息 |
| 账号权益 | 不修改角色、背包或装扮拥有状态 | 在本地呈现与实际拥有状态不同的内容 |
| 对局决策 | 不提供出牌建议或自动操作 | 取决于具体工具，不属于此处比较范围 |

### 工作原理与保护措施

扩展使用游戏已有的役满控制器，由游戏自身提供实际和牌手牌。在经过校验的资源中，仅调整动画入口、特效资源加载和音效处理三处逻辑。

替换仅作用于匹配资源的只读文件描述符，原始持久缓存内容和写入路径保持不变。扩展会校验框架与资源指纹；遇到未知版本或校验失败时，停止本次页面加载中的后续替换，不尝试强行适配。

这些设计减少了与账号数据、游戏通信及无关逻辑的接触，有助于降低误修改和兼容性问题。**但技术保护不等于官方授权，也不能证明封号概率更低。** Yakuman FX 仍属于非官方客户端修改，可能导致账号限制或封禁，不提供账号安全保证。

## 快速安装

**下载 → 解压 → 加载扩展 → 大厅启用**

1. 从 [Releases](https://github.com/Chaldeaaa/yakuman-fx/releases) 下载并解压 `yakuman-fx-v0.3.1.zip`。
2. 打开 `edge://extensions` 或 `chrome://extensions`，开启 **开发者模式**。
3. 点击 **加载解压缩的扩展**，选择包含 `manifest.json` 的文件夹。
4. 打开支持的雀魂入口，停留在大厅，点击扩展内的 **启用并刷新**。
5. 确认大厅提醒，等待状态显示 **原生特效已就绪**

> [!IMPORTANT]
> 保留解压后的文件夹。**不要在对局中刷新游戏。**

以后加载游戏会自动启用，无需 Node.js、Python 或本地服务器。浏览器可能提示正在使用开发者模式扩展。

详细的文件夹选择、首次启用、更新及卸载步骤见 [安装教程](docs/INSTALL.zh-CN.md)。本项目通过手动安装分发，不通过扩展商店发布。

## 恢复与更新

**语言与外观：** 点击弹窗右上角齿轮，在设置中选择英文／简体中文，以及浅色／深色／跟随系统主题。设置会保存，并同时应用于弹窗和设置页。

**恢复：** 点击 **恢复默认**，然后在大厅刷新游戏，移除当前页面已加载的临时修改。卸载时，在浏览器扩展管理页移除扩展，并刷新游戏。

**更新：** 打开 **设置 → 检查更新**。发现新版后，通过发布页面下载扩展 ZIP。关闭游戏，将新版文件解压并覆盖原安装文件夹，在浏览器扩展管理页点击 **重新加载**，再打开游戏。更新需要手动安装；仅在点击按钮时检查更新。

## 常见问题

| 状态或现象 | 处理方式 |
| --- | --- |
| 自动特效已启用 | 回到大厅刷新游戏，以应用已保存的设置。 |
| 正在加载原生特效 | 等待游戏加载完成。若进入大厅后仍停留在此状态，请刷新一次。 |
| 资源加载失败 | 检查网络连接，然后在大厅重试。 |
| 游戏资源不匹配 | 在设置中检查更新。如果已是最新版，请在反馈问题时附上启动诊断。 |
| 原生特效已就绪，但没有动画 | 提供浏览器及扩展版本、游戏入口、牌谱信息和启动诊断。 |
| 检查更新失败 | 检查网络后重试，或点击设置中的 **打开发布页面**。 |

点击弹窗右上角齿轮，在设置中展开 **问题排查**，即可查看已保存的启动诊断。反馈时不要上传账号凭据、认证令牌或浏览器配置文件。

## 实现方式

已检查的 WebGL 客户端保留了原生役满控制器，但关闭了动画入口并跳过相应资源组。扩展恢复这两条路径，同时修正飞牌音效通道。实际和牌手牌由游戏控制器提供，不是播放录像。

扩展校验官方框架和资源包，在本地执行三处等长脚本修改，再将验证通过的读取指向 Unity 临时虚拟文件。原持久缓存写入不变，未知资源会被拒绝修改。

没有分析统计、广告、遥测服务或开发者运营的服务器。官方资源从游戏域名或官方资源 CDN 下载并在本地处理。扩展不拦截游戏 WebSocket 消息，也不主动读取账号凭据；这些行为不构成账号安全保证。检查更新仅在用户点击时联系 GitHub。权限和数据处理详情见 [隐私说明](PRIVACY.md)。

## 开发

测试需要 Node.js 22 或更新版本：

```sh
npm test
```

测试覆盖资源处理与缓存、补丁修改范围、异常处理、消息合并、双语恢复提示和发布版本比较。自动测试不能替代动画和音效播放验证。

使用 Python 3 打包扩展：

```sh
python scripts/package.py
```

安装包输出到 `dist/`。GitHub Actions 自动运行测试并构建版本化发布。发布流程见 [分发说明](DISTRIBUTION.md)，后续计划见 [路线图](ROADMAP.md)。
